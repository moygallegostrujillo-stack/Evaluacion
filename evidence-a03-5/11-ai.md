# A-03.5 — PASO 13: IA
## La IA puede producir DRAFT items — nunca gobernar el modelo canónico

## Línea implementada

La IA (ruta RH-triggered `/api/vacancies/[id]/generate-questions`) sigue
generando preguntas para el banco de la vacante, pero ahora con **procedencia
marcada**:

```ts
// generate-questions/route.ts (PASO 13)
await rlsDb.vacancyQuestion.create({
  data: { ..., origin: 'AI_DRAFT' },
})
```

- `VacancyQuestion.origin`: `RH_MANUAL` (ruta RH) | `AI_DRAFT` (ruta IA) | null (pre-A-03.5).
- El marcado viaja a la cadena canónica: el requirement derivado recibe
  `source = 'AI_DRAFT_ORIGIN'` y el KnowledgeItemVersion `source = 'AI_DRAFT'`
  — trazabilidad de procedencia permanentemente visible.

## Qué NO puede hacer la IA (verificado por auditoría de superficie)

| Prohibición | Mecanismo |
|---|---|
| Crear Blueprint APPROVED | Cero rutas de escritura hacia KnowledgeBlueprint; se crea SOLO dentro del freeze SYSTEM |
| Crear Requirement APPROVED | Ídem — derivación SYSTEM exclusivamente |
| Publicar Assessment | `publishedBy` siempre 'SYSTEM:KNOWLEDGE_FREEZE' / 'SYSTEM:PUBLIC_APPLY_FREEZE' (A-03.4); ninguna ruta IA/HTTP publica |
| Aprobar correctAnswer | La clave que propone la IA vive como dato del banco; la aprobación es implícita al proceso RH→banco→SYSTEM publish; IA no toca tablas canónicas |
| Modificar Assessment ACTIVE | Sin rutas de actualización; immutabilidad por diseño (solo transición ACTIVE→RETIRED por SYSTEM) |
| Cambiar versiones | assessmentVersion/blueprintVersion/itemVersion se derivan server-side; ninguna entrada cliente/IA los afecta |

## Deny-list extendida (cliente)

`blueprintId`, `requirementId`, `itemVersionId`, `knowledgeAdministrationId`,
`knowledgeResultId`, `evidenceStatus`, … → 403 MANIPULATION_REJECTED
(SEC-1a..d). La IA tampoco es cliente de estos campos: simplemente no existe
ruta que los acepte.

## Auditoría de superficie (solo lectura del árbol de imports)

- Rutas que tocan entidades canónicas: `/api/public/apply` (freeze/scoring),
  `/api/evaluations` (freeze/serving/scoring interno),
  `/api/vacancies/[id]/knowledge-versions` (lectura RH, sin claves).
- Rutas IA (`generate-questions`): SOLO escriben `VacancyQuestion` con
  `origin='AI_DRAFT'`. Ningún import de knowledge-canonical/knowledge-versioning.

Conclusión: la IA es **borradorista** (KPUB/KGOV), el ciclo completo de
gobernanza permanece RH (banco) → SYSTEM (publicación canónica).
