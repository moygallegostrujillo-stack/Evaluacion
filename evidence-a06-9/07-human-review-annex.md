# ANEXO 2 — REVISIÓN HUMANA

## 1. Flujo obligatorio

```
ENTREVISTA (entrevistador humano)
   → EVIDENCIA (fragments confirmados por humano; lo de IA es AI_DRAFT sin efecto)
   → REVISIÓN HUMANA (revisor humano distinto, con rúbrica aprobada)
   → RESULTADO DE COMPETENCIA (nivel asignado por persona, con justificación)
   → [empresa cliente] DECISIÓN LABORAL (humana, fuera de EvaluHR)
```

Queda prohibida cualquier variante del tipo IA → DECISIÓN.

## 2. Quién revisa

| Regla | Contenido |
|---|---|
| RH-1 | El **revisor** es una persona designada por EvaluHR conforme al alcance contratado; puede participar el revisor de la empresa cliente (revisión compartida). |
| RH-2 | El revisor **no puede ser el entrevistador de la misma sesión**, salvo las excepciones documentadas y controladas (EX-1..EX-4 del diseño metodológico A-06.7), siempre registradas como excepción. |
| RH-3 | El revisor aplica la **rúbrica aprobada** (cualitativa, por indicadores) y el protocolo de calibración; no aplica scoring numérico ni cortes automáticos. |
| RH-4 | El revisor puede **invalidar** evidencia contaminada (p. ej., contenido de revelación involuntaria) con justificación, mediante append-only. |

## 3. Cómo se documenta

| Elemento | Registro |
|---|---|
| Asignación de nivel | Nivel + justificación textual basada en evidencia citada + autor + fecha/hora + versión de rúbrica |
| Versiones | Append-only: toda corrección es nueva versión; no se sobrescribe |
| Conflictos | Resolución documentada cuando existan inconsistencias (CV vs entrevista vs referencias) |
| Trazabilidad | Cadena completa pregunta → evidencia → nivel → resultado, auditable |
| Excepciones | Cada revisión con entrevistador=revisor queda registrada como excepción con controles |

## 4. Qué no hace la revisión humana

- No usa salidas de IA como base única.
- No usa reflexiones de cierre ni información sensible revelada como evidencia.
- No determina contratación: eso corresponde exclusivamente a la empresa cliente.
