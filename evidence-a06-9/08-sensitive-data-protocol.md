# ANEXO 3 — PROTOCOLO DE DATOS SENSIBLES EN ENTREVISTA

## 1. Regla general

La entrevista estructurada **no solicita datos sensibles**. El proceso está diseñado para tratar
únicamente conducta laboral pasada (Situación, Tarea, Acción, Resultado).

## 2. Protocolo si el candidato revela espontáneamente un dato sensible

| # | Obligación |
|---|---|
| 1 | **No se profundiza**: el entrevistador no indaga, no confirma ni comenta el contenido del dato. |
| 2 | **No se utiliza para valorar competencia**: el dato no alimenta indicadores, niveles, rationale ni decisiones. |
| 3 | **No se registra su contenido si no es necesario**: no se anota en notas, campos libres ni transcripciones; se retoma la conducta laboral en curso. |
| 4 | **Se redirige la entrevista**: se retoma de inmediato la pregunta de competencia (guion de contención del entrenamiento). |
| 5 | **Se documenta únicamente el incidente mínimo indispensable**: bandera de auditoría con fecha/hora y competencia en curso, **sin el contenido del dato**. |

## 3. Reglas complementarias

1. Si el contenido apareciera registrado pese al protocolo: **invalidación** de la evidencia
   afectada (append-only) y eliminación del contenido.
2. Si existiera transcripción, el segmento sensible se elimina en cuanto se identifique.
3. La bandera del incidente es visible solo para revisión/auditoría; **no para quien decide
   contratación**.
4. Cuando exista riesgo jurídico (candidato insiste, queja, duda del manejo), se activa **revisión
   humana con posible escalación legal**.
5. La ausencia de respuesta sobre un tema personal no penaliza ninguna competencia.

## 4. Excepciones

Cualquier necesidad de tratamiento de datos sensibles (p. ej., un futuro BFOQ) queda sujeta al
procedimiento de excepción documentado (justificación específica del puesto, dictamen legal,
aprobación humana dual y consentimiento expreso). **[LEGAL_REVIEW]**. Estado actual: **0
excepciones activas**.
